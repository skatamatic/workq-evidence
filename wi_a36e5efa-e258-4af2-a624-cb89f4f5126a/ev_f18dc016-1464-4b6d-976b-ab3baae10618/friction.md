# Onboarding UX friction (isolated full e2e)

Generated by `test:harness:onboarding-full` while flexing wizard options.

## friction

- **welcome — Prerequisites buried:** No prerequisites disclosure found.
- **size — Capacity before host stats:** The step says host resources are unavailable and falls back to a stated default. Operators who Continue quickly never see a real core count — either wait for the daemon heartbeat or say the default is a first-run guess.
- **trackers — Trackers before GitHub credentials:** GitHub Issues reuses the GitHub named credential, but Forges (where that PAT is entered) is the next step. Enabling Issues here cannot prove ready yet.
- **forges — Two primary buttons:** Step panel has 2 .btn.primary (Add integration · Replace credentials). Easy to click the wrong one.
- **repo-bind — CI bind after skipped CI:** Connect-repo still asks for a CI override even when the fleet CI step left CircleCI/Jenkins unavailable. Inherit of “nothing configured” is confusing.
- **evidence — Cap draft silently locks Continue:** Picking a lower cap disables Continue until Apply cap or Keep current bar. Easy to look stuck.
- **smoke — Run smoke and Continue both look primary:** The in-panel Run smoke button is .btn.primary next to a locked footer Continue. After a successful claim the wizard auto-completes — Continue can be a no-op and the success copy never gets a beat.
